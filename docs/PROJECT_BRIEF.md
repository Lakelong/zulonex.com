# 逐鹿未来&星鹿爱学 三端导学 AI成长系统｜项目简报

> 版本：M1 产品架构与实施方案 v0.4（已确认）  
> 更新时间：2026-08-13  
> 适用阶段：M1 本地 Demo  
> 状态：已于 2026-08-10 获用户批准并授权主线实施  
> 基线关系：v0.3 仅保留为历史事实；v0.4 是当前唯一有效实施基线

## 已确认

### 项目背景

逐鹿未来需要让城市及服务点运营主体自主创建本地内容，同时由总部统一进行品牌治理、合规审核和最终公开控制。项目不是传统站群或复杂 CMS，而是一套以官网为内容母站、由总部统一治理的城市服务官网与内容协同平台。

### 品牌与命名口径

- 对外品牌：**逐鹿未来**。
- 面向用户的产品/服务品牌：**逐鹿未来&星鹿爱学 三端导学 AI 成长系统**。
- 平台及项目正式名称：**逐鹿未来&星鹿爱学 三端导学 AI成长系统**。
- 网站 Logo 文案：**逐鹿未来 · 星鹿爱学 · 三端导学 AI成长系统**。
- 内部简称：**逐鹿 GEO AI 内容中台**。
- 对外统一表述：**城市服务官网与内容协同平台**。
- 对外不得强调“站群、霸屏、收录矩阵”。

### 产品定义

> 以官网为可信内容母站，以代理商内容发布台为城市/门店内容创建入口，以总部内容运营台为品牌治理、合规审核与最终公开控制中枢，以 AI 内容治理引擎为生产力中台，以全渠道分发中心为增长放大器的城市服务官网与内容协同平台。

### v0.4 已确认架构定义

- **业务产品**：逐鹿未来&星鹿爱学 三端导学 AI 成长系统。
- **面向外部的平台表述**：城市服务官网与内容协同平台。
- **内部平台名称**：逐鹿 GEO AI 内容中台。
- **数字平台形态**：一个公开官网 + 一个统一内容协同后台 + 代理商/总部两种角色权限 + 一条品牌治理发布链路。
- 公开官网是唯一独立公开端；代理商与总部共用统一后台和同一内容数据模型，通过 RBAC 视图区分。
- AI、分发、事实库、CRM 是平台能力或后续数据底座，不是 M1 独立系统。
- “三端导学”是业务与教育服务概念，不代表本数字平台的公开端、代理商端、总部端。

### 统一后台定位

统一后台定位为“逐鹿未来面向代理商的内容运营、培训赋能与品牌协同平台”。代理商在其中创作和复用内容、获取活动/课程/素材与优秀实践；总部在同一后台治理品牌风险、提供官方资源并控制最终公开。

### 生产交付模型

总部统一建设并运营一套系统，不为每个代理商复制部署网站、后台、服务器或数据库。代理商获得经授权的官网空间/服务范围、后台账号和资源包；总部统一管理公开官网、协同后台、数据库、素材、审核、资源、日志与运维。生产化边界和 M2 技术方案见 [PRODUCTION_DELIVERY_AND_TECHNICAL_PLAN.md](./PRODUCTION_DELIVERY_AND_TECHNICAL_PLAN.md)。

### 项目目标

- 让代理商作为城市/门店内容运营发布主体，以接近朋友圈、小红书、公众号或抖音创作的轻量体验创建内容。
- 用 AI 初审与人工终审提高内容处理效率，同时守住真实性、隐私和品牌合规底线。
- 形成一份可信的官网母版内容，并从母版派生不同渠道的内容包。
- 打通“创建内容—AI 检查—总部审核—公开发布—渠道分发—反馈回收”的闭环。
- 为后续事实库、CRM、云部署、城市试点及社媒 API 对接提供可扩展基座。

### 当前阶段

当前为 **M1 本地 Demo**。演示城市为合肥市，采用真实城市语境；门店、代理商、学员、案例和联系方式均使用虚拟演示信息，并统一标注“演示数据，不代表真实运营信息”。服务点可使用“合肥示范服务点 A/B”等明显演示名称。

合肥是数据语境和演示范围，不是全站重复宣传标签。城市只出现在城市切换、服务范围、服务点、活动地点、联系方式、地域内容和页面元信息等确有地域意义的位置；产品介绍、通用服务方法和通用栏目不强加城市前缀。

### 成功标准

- 四段 Demo 闭环可以连续演示，关键状态可见且前后对应。
- 代理商可在 3 分钟内完成一条图文内容创建和送审。
- 支持基本排版、多图插入、桌面/移动预览和保存草稿。
- 必须完整演示“退回修改—重新提交—审核通过—公开发布—下架”。
- 总部能看到 AI 初审依据，并明确执行确认或退回。
- 已确认内容可生成渠道内容包、分发任务并记录反馈。
- 公开站只展示已确认发布的内容。
- Demo 数据与真实数据有明确标识，不产生自动公开发布。
