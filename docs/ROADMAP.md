# 项目路线图

> 版本：M1 产品架构与实施方案 v0.4（已确认）  
> 更新时间：2026-08-13  
> 适用阶段：当前为 M1 本地 Demo；路线覆盖后续阶段  
> 状态：已于 2026-08-10 获用户批准并授权主线实施

## 已确认

### M1：本地 Demo（当前）

**目标**：用合肥市演示语境验证代理商内容发布、AI 检查、总部退回重提、审核发布、官网展示和下架闭环。  
**P0 交付**：合肥公开站、`/console` 统一后台、`/console/content/new` 轻量图文编辑器、草稿/预览/AI 检查、总部审核队列、退回重提、通过发布、下架、状态和审核记录。  
**P1 交付**：统一后台内的渠道内容包、人工发布任务及链接/截图/数据反馈演示；M1-D 已纳入 M1 验收。  
**前置条件**：确认 P1 渠道格式、验收人和演示方式。  
**主要风险**：把模拟能力误认为生产能力；不同页面使用不一致的内容状态。

v0.4 将 M1 拆为：M1-A 统一后台骨架与角色切换；M1-B 创作审核闭环；M1-C 总部资源协同（P0）；M1-D 轻量渠道分发（纳入 M1 验收）；M1-E 双端、双角色与四条闭环验证。具体实施顺序见 `IMPLEMENTATION_PLAN_M1.md`，主线已获授权执行。

### M2：生产技术方案与后端 Beta 基础

**目标**：完成生产技术方案、统一数据模型、账号/RBAC、后端 API、关系型数据库、对象存储、AI 接入和测试环境。  
**前置条件**：M1 用户验收通过；数据模型、组织权限、隐私规则、授权存证、供应商、预算和安全方案评审通过。  
**主要风险**：历史资料质量不一；未成年人数据和图片授权不完整；数据迁移成本。

### Beta：合肥受控线上测试

**目标**：让合肥少量真实授权主体使用真实账号、内容审核和总部资源，在受控测试环境验证生产闭环。  
**前置条件**：M2 技术方案、安全、备份、合规和测试环境通过评审。  
**主要风险**：越权、授权缺失、数据泄露、审核积压和恢复失败。

### 正式试点：上线与运营复盘

**目标**：完成适用的接入备案、HTTPS、DNS、真实代理商官网空间开通、运营支持和指标复盘。  
**前置条件**：Beta 通过权限、安全、备份、恢复和合规验收。  
**主要风险**：域名与备案周期、敏感数据保护、发布回滚和运行成本。

### 规模化：批量开通与能力渐进

**目标**：批量开通官网空间，标准化培训和资源供给，按需渐进接入 CRM、分发和官方 API。  
**前置条件**：正式试点指标和总部运营支持能力达到扩展门槛。  
**主要风险**：平台政策变化、账号风控、接口限制、内容重复和错误规模化扩散。

### 阶段门禁

M1 验收后才进入 M2；M2 生产方案评审后才创建云资源；Beta 通过权限、安全、备份、恢复和合规验收后才进入正式试点。详细闸门见 [ACCEPTANCE_MATRIX.md](./ACCEPTANCE_MATRIX.md)。

## 待确认

- M2 云服务商、地域、容量、预算和采购主体。
- 数据库、对象存储、AI 服务、身份认证和通知技术选型。
- 正式域名、官网空间 URL、组织/运营范围和 CRM 接入方案。
- Beta 授权主体、试点指标、支持 SLA、安全与合规结论。

## 当前不做

当前 M1 不执行 M2、Beta、正式试点或规模化阶段的真实系统接入、采购、部署、域名、运营或社媒 API 调用。生产方案见 [PRODUCTION_DELIVERY_AND_TECHNICAL_PLAN.md](./PRODUCTION_DELIVERY_AND_TECHNICAL_PLAN.md)。
